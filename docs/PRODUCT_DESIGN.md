# PPOZ 产品设计文档（MVP 版）

> 版本：v0.2 · 日期：2026-08-30 · 状态：技术选型定稿

## 1. 产品定位

**PPOZ 是一款朋友之间专用的游戏语音开黑软件。**

不做大而全的社区平台，只解决一件事：让一群朋友以最短的路径、最稳的音质开上黑。核心体验链路：

> 群里喊一声 → 点链接进房 → 全员开麦 → 开打

差异化主张：**进房快、音质稳、游戏全屏时不掉链子**——瞄准的是 Discord/YY 在真实开黑场景中被诟病最多的痛点。

## 2. 目标用户与场景

- **用户**：固定车队 / 开黑小圈子（3~10 人），彼此认识，无陌生人社交需求
- **设备**：以 PC 为主（开黑场景 90% 在桌面端），MVP 不做移动端
- **典型场景**：晚间约局、临时拉队、游戏全程持续通话（2~4 小时）

## 3. MVP 功能范围

### 3.1 核心（这一版必须做）

| 模块 | 功能点 | 说明 |
|------|--------|------|
| 房间 | 一键建房 | 输入昵称即可创建，无需注册账号 |
| 房间 | 链接/口令进房 | 朋友点链接直接进房，进房链路 ≤ 30 秒 |
| 语音 | 多人实时语音 | 6~10 人房间，低延迟，带降噪与回声消除 |
| 语音 | 语音控制 | 麦克风开关（开即常开说话，关则他人听不到）、静音他人、说话人高亮 |
| 房间 | 房间管理 | 房主可踢人、锁房 |

### 3.2 暂缓（有用户反馈后再评估）

- 文字聊天、屏幕共享（微信/QQ 群已覆盖）
- 好友系统、服务器/频道体系（房间链接即入口）
- 账号体系、付费、皮肤、管理后台
- 移动端、桌面客户端打包（MVP 先做 Web 版验证）

## 4. 技术方向（概要）

| 层次 | 方案 | 理由 |
|------|------|------|
| 前端 | **React + TypeScript** | 生态最大、资料最多，学完通用性最强；与 LiveKit 官方 React SDK 天然契合 |
| 语音引擎 | **LiveKit 自建（开源 SFU，Apache 2.0，永久免费）** | 不自研音频栈；架构透明、学习价值高；单机即可带几个小房间，零软件费用 |
| 服务端 | **NestJS + TypeScript** | 与前端同一种语言，学习成本减半；官方 WebSocket 网关适配房间广播场景 |
| 房间状态 | **Redis（内存）**，暂不上数据库 | MVP 无账号体系，房间是易失的临时数据，人散即灭 |
| 实时通信 | **WebSocket** | 房间状态（进/退/静音/踢人）天然适合长连接 |
| 客户端形态 | Web 版优先，后续 Tauri/Electron 打包桌面端 | 验证最快，分发零成本 |

**已锁定选型**（立项评审已确认）：React + TypeScript / NestJS + Redis / LiveKit 自建。
核心原则：**控制流与音频流分离**——房间状态走自有 WebSocket，音频流走 LiveKit 转发，两条线互不干扰（经典 Discord 式架构）。
**成本说明**：LiveKit 软件本身免费，唯一开销是一台有公网 IP 的轻量服务器（约 ¥40~60/月）；开发阶段可本机 + Docker 局域网直连、用免费内网穿透（frp/cpolar）临时暴露端口，零成本验证。若后续需要更强弱网表现，客户端接入层可平滑切换到 TRTC/Agora，架构已预留切换位。

## 5. 体验硬指标（MVP 验收标准）

1. 5 个朋友从群里点链接到全部开上麦，全程 ≤ 30 秒
2. 一局完整游戏（2 小时+）通话，无掉线、无明显音质劣化
3. 游戏全屏运行时，麦克风采集正常工作（PTT 已移除，麦克风开关即常开说话）
4. 弱网（丢包 20%）下仍可通话（允许降质，不允许中断）

## 6. 里程碑

| 阶段 | 内容 |
|------|------|
| M1 | 技术选型敲定 + 项目骨架搭建 |
| M2 | 房间创建/加入 + 基础多人语音跑通 |
| M3 | 语音控制（麦克风开关/静音/高亮）+ 房间管理 |
| M4 | 内测：自己车队真实开黑使用 2 周，修复问题后交付 MVP |

## 7. 非目标（明确不做）

- 不做陌生人匹配、公会/社区运营
- 不做直播、K 歌等泛娱乐功能
- MVP 阶段不考虑商业化
