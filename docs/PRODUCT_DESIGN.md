# PPOZ 产品设计文档（MVP 版）

> 版本：v0.3 · 日期：2026-08-30 · 状态：零成本方案定稿（P2P）

## 1. 产品定位

**PPOZ 是一款朋友之间专用的游戏语音开黑软件。**

不做大而全的社区平台，只解决一件事：让一群朋友以最短的路径、最稳的音质开上黑。核心体验链路：

> 群里喊一声 → 点链接进房 → 全员开麦 → 开打

差异化主张：**进房快、音质稳、游戏全屏时不掉链子**——瞄准的是 Discord/YY 在真实开黑场景中被诟病最多的痛点。

## 2. 目标用户与场景

- **用户**：固定车队 / 开黑小圈子（3~6 人），彼此认识，无陌生人社交需求
- **设备**：以 PC 为主（开黑场景 90% 在桌面端），MVP 不做移动端
- **典型场景**：晚间约局、临时拉队、游戏全程持续通话（2~4 小时）

## 3. MVP 功能范围

### 3.1 核心（这一版必须做）

| 模块 | 功能点 | 说明 |
|------|--------|------|
| 房间 | 一键建房 | 输入昵称即可创建，无需注册账号 |
| 房间 | 链接/口令进房 | 朋友点链接直接进房，进房链路 ≤ 30 秒 |
| 语音 | 多人实时语音 | 最多 6 人房间，低延迟，带降噪与回声消除 |
| 语音 | 语音控制 | 麦克风开关（开即常开说话，关则他人听不到）、静音他人、说话人高亮 |
| 房间 | 房间管理 | 房主可踢人、锁房 |

### 3.2 暂缓（有用户反馈后再评估）

- 文字聊天、屏幕共享（微信/QQ 群已覆盖）
- 好友系统、服务器/频道体系（房间链接即入口）
- 账号体系、付费、皮肤、管理后台
- 移动端、桌面客户端打包（MVP 先做 Web 版验证）

## 4. 技术方向（概要）

目标约束：**全程零成本**——不购买任何服务器，音频流不经过服务器。

| 层次 | 方案 | 理由 |
|------|------|------|
| 前端 | **React + TypeScript** | 生态最大、与 WebRTC 原生契合 |
| 语音引擎 | **WebRTC P2P mesh（浏览器直连）** | 音频在成员浏览器间直接传输，不经任何服务器，¥0 |
| NAT 穿透 | **公共免费 STUN**（Google `stun.l.google.com`） | 帮家用宽带（锥形 NAT）打通直连，无需自建，¥0 |
| 信令 | **免费云函数**（Cloudflare Workers / Supabase Realtime 免费档）或 本机 + 免费组网（ZeroTier/Tailscale） | 仅转发连接信息（SDP），不传语音；免费额度足够，¥0 |
| 房间状态 | 信令层内存 / 免费 KV（Cloudflare KV / Supabase） | 房间是易失临时数据，无需独立付费 Redis |
| 实时通信 | **WebSocket / WebRTC DataChannel** | 房间状态同步 |
| 客户端形态 | Web 版优先，后续 Tauri/Electron 打包桌面端 | 验证最快，分发零成本 |

**已锁定选型**：React + TypeScript / WebRTC P2P mesh / 免费云函数信令（或本机 + 免费组网）。
核心原则：**音频走 P2P 直连、信令走免费云**——彻底去掉常驻媒体服务器（即上一版考虑的 LiveKit 被放弃：它需要一台常驻服务器，违背零成本约束）。

**零成本取舍（必须知晓）**：
1. 人数上限：P2P mesh 下每人向其他每个人各发一份音频，3~6 人很轻松，10 人会吃满房主上行带宽。**MVP 房间上限固定为 6 人**，创建房间即按此上限校验，满员后拒绝新成员进房。
2. 对称型 NAT：极少数公司网络 / 部分移动网是对称 NAT，纯 P2P 可能连不上，需要 TURN 中转（唯一可能花钱的坑）。家用宽带多为锥形 NAT，STUN 即可打通；可用 ZeroTier/Tailscale 免费组网规避（组网后像局域网，无需穿透）。
3. 本机方案需房主开机：若用「本机 + 免费组网」跑信令，你不开机朋友就进不来；用免费云函数方案则随时可进。

## 5. 体验硬指标（MVP 验收标准）

1. 5 个朋友从群里点链接到全部开上麦，全程 ≤ 30 秒
2. 一局完整游戏（2 小时+）通话，无掉线、无明显音质劣化
3. 游戏全屏运行时，麦克风采集正常工作（PTT 已移除，麦克风开关即常开说话）
4. 弱网（丢包 20%）下仍可通话（允许降质，不允许中断）

## 6. 里程碑

| 阶段 | 内容 |
|------|------|
| M1 | 技术选型敲定 + 项目骨架搭建 |
| M2 | 房间创建/加入 + 基础多人语音跑通 |
| M3 | 语音控制（麦克风开关/静音/高亮）+ 房间管理 |
| M4 | 内测：自己车队真实开黑使用 2 周，修复问题后交付 MVP |

## 7. 非目标（明确不做）

- 不做陌生人匹配、公会/社区运营
- 不做直播、K 歌等泛娱乐功能
- MVP 阶段不考虑商业化
